# سامانه مدیریت فروشگاه خوراک دام و طیور

پنل فارسی، راست‌چین و واکنش‌گرا برای مدیریت کالا، خرید، فروش، برگشت کالا، حساب اشخاص، هزینه‌ها، گردش بانک و گزارش ماهانه. رابط برای استفاده روزانه طراحی شده و نسخهٔ PWA آن می‌تواند فایل‌های برنامه را برای دسترسی آفلاین نگه دارد.

## فناوری و ساختار

این پروژه یک وب‌سایت استاتیک HTML/CSS/JavaScript بدون فرایند build است. داده‌ها در Supabase ذخیره می‌شوند و برنامه با اتصال اینترنت همگام می‌شود. فایل `config.js` تنظیمات عمومی اتصال را نگه می‌دارد؛ کلید محرمانهٔ `service_role` نباید در مرورگر، GitHub یا `config.js` قرار بگیرد.

## راه‌اندازی دیتابیس

مخزن حاضر شامل فایل پایهٔ قدیمی `supabase/schema.sql` و `supabase/seed.sql` نیست؛ برای دیتابیس تازه ابتدا باید schema پایهٔ سازگار با نسخهٔ قبلی برنامه آماده و اعمال شود. پس از وجود جدول‌های پایهٔ `products`، `sales`، `purchases`، `expenses` و `profiles`، فایل `supabase/migrations/20261127000000_workbook_sections.sql` را در SQL Editor همان پروژه اجرا کنید. این migration ستون‌های تکمیلی و جدول‌های برگشت کالا، طرف حساب و گردش بانک را می‌سازد و برای جدول‌های تازه فقط خواندن کاربران واردشده و نوشتن مدیر را مجاز می‌کند. پیش از اجرا روی محیط کاری واقعی، از دیتابیس نسخهٔ پشتیبان تهیه کنید.

در `config.js` آدرس پروژه و کلید عمومی anon پروژه را تنظیم کنید. سیاست‌های RLS برای جدول‌های قدیمی نیز باید فعال و متناسب با نقش‌های پروژه باشند. برنامه فعلی از ورود Supabase استفاده می‌کند؛ رابط ورود، نام کاربری را به الگوی ایمیل `نام‌کاربری@shop.local` تبدیل می‌کند و نقش را از `profiles.role` می‌خواند. **هیچ حساب کاربری یا گذرواژه‌ای در این مخزن ایجاد یا تنظیم نشده است.** افزودن حساب‌ها باید فقط در زمان و روش مورد تأیید صاحب فروشگاه انجام شود.

## هماهنگی با فایل اکسل

ساختار و واژگان رابط با هشت بخش فایل مرجع هماهنگ شده است: فهرست کالاها، خرید، فروش، برگشت کالا، بدهکاران و بستانکاران، هزینه‌ها، بانک و قرض، و گزارش ماهانه. گزارش ماهانه در برنامه از رکوردهای ثبت‌شده محاسبه می‌شود: فروش کل، برگشتی‌ها، فروش خالص، بهای تمام‌شده، سود ناخالص، هزینه، سود خالص و حاشیه سود. **داده‌ها و سوابق مشتریان/مالی فایل اکسل به‌طور خودکار وارد برنامه نمی‌شوند.**

در صفحهٔ انبار، موجودی هر کالا از موجودی اولیه + خریدها + برگشتی‌ها − فروش‌ها به دست می‌آید. این همان ساختار تجمیع خرید و فروش برگهٔ «فهرست کالاها» است؛ با این تفاوت که فرمول فعلی اکسل برگشتی‌ها را در مانده وارد نمی‌کند، اما برنامه آن‌ها را به‌عنوان گردش ورودی جداگانه لحاظ می‌کند. وضعیت بحرانی برای موجودی صفر یا کمتر، نیاز به سفارش برای موجودی مثبت تا نقطهٔ سفارش، و کافی برای موجودی بالاتر از آن است. ارزش موجودی از موجودی مثبت فعلی × قیمت خرید محاسبه می‌شود. صفحهٔ انبار خلاصهٔ تعداد کالاها، شمار کمبودها و ارزش موجودی را نشان می‌دهد؛ جست‌وجو و فیلتر دسته/وضعیت دارد و خروجی CSV بر اساس فیلترهای فعال ساخته می‌شود. مدیر می‌تواند از ردیف کالای کم‌موجود فرم خرید همان کالا را باز کند.

## اجرا و استقرار

برای توسعه می‌توان یک وب‌سرور استاتیک را از ریشهٔ مخزن اجرا کرد. فایل `index.html` نقطهٔ ورود است و نیازی به build ندارد. استقرار روی میزبان استاتیک نیازمند HTTPS است تا service worker و قابلیت نصب PWA در مرورگرها فعال شوند. مسیر اصلی صفحه در `manus-routes.json` ثبت شده است.

## فاکتور و آفلاین

در صفحهٔ فروش، فاکتور ثبت‌شده را می‌توان چاپ کرد یا از پنجرهٔ چاپ مرورگر به PDF ذخیره کرد. برگشت فقط از ردیف فروش ثبت‌شده انتخاب می‌شود و مقدار آن از مقدارِ برگشت‌نخورده بیشتر نمی‌شود؛ بهای تمام‌شده برگشتی از همان ردیف فروش برداشته می‌شود. محاسبهٔ موجودی برابر است با موجودی اولیه + خریدها + برگشت‌ها − فروش‌ها. هنگام قطع اینترنت، تغییرات در مرورگر نگه داشته می‌شوند و پس از اتصال مجدد برای همگام‌سازی ارسال می‌شوند؛ خطای اعتبارسنجی یا دسترسی نیز صف را نگه می‌دارد تا دادهٔ محلی بی‌صدا دور ریخته نشود. تا پایان همگام‌سازی، داده‌های محلی همان مرورگر را پاک نکنید.

کتابخانه‌های JavaScript موردنیاز برنامه داخل `vendor/` نگهداری می‌شوند تا بارگذاری برنامه پس از نصب PWA به CDN وابسته نباشد. فونت وب در نبود اینترنت ممکن است با فونت جایگزین نمایش داده شود. ماندهٔ اشخاص جمع محاسباتی ماندهٔ آغازین و اسناد نسیه/چکی است؛ ثبت دریافت/پرداخت برای تسویه و پیوند پایدار نام‌های اشخاص در نسخهٔ فعلی پیاده نشده، بنابراین این نما هنوز دفترکل تسویه‌شده نیست.
